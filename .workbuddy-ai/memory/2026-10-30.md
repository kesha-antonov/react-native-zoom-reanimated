# 2026-10-30

## PR `feature/add-single-tap-callback` — maintainer review fixes

Branch adds an `onTap` (single tap) callback to `<Zoom />` / `useZoomGesture*`.
Applied the review feedback from kesha-antonov:

- `src/useZoomGestureCore.ts`: `handleTapEnd` now calls `runOnJS(onTap)({ x, y })` (was a
  synchronous JS call inside a worklet — would throw on the UI thread). Added `hasOnTap`
  to `ZoomGestureCore` so adapters know whether to attach the single-tap recognizer.
- `src/useZoomGestureV2.ts` / `V3.ts`: single-tap gesture is `.enabled(hasOnTap)` /
  `enabled: hasOnTap`, so no idle tap recognizer steals taps when `onTap` is absent.
- `src/gestureApi.ts`: added `enabled?: boolean` to `V3CommonConfig` (verified against
  RNGH 3.1.0 `v3/types/ConfigTypes.d.ts`); `useExclusiveGestures` exists in RNGH 3.1.0.
- `src/types.ts`: `import type { ZoomTapEvent }` (breaks the value-level cycle), reverted
  unrelated reformatting; public payload documented as plain `{ x, y }`.
- `src/Zoom.tsx`: dropped the unused `onTap` on `ZoomViewProps`.
- Docs: README section + props table row + hook API, CHANGELOG "Unreleased", example
  `App.tsx` basic screen shows last tap position, `example/EXAMPLES.md`.
- `example/__tests__/gestureApi.test.tsx`: mocks were missing `Gesture.Exclusive` /
  `useExclusiveGestures` (the PR broke them); added those plus tests for enabled-flag and
  the `{ x, y }` payload.
